# App Icon Integration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Wire the app icon from `design_files/MediaMerger Design Help-v1.0.3-handoff.zip` into the running window, the `.desktop` entry, and the standard hicolor icon theme via packaging.

**Architecture:** New `mediamerger-app/assets/app-icon/` directory holds the master SVG, symbolic SVG, and a 128px PNG. The PNG is decoded to raw RGBA8 at startup (new minimal `image` dependency) and set as the `iced::window::Settings.icon`. The two SVGs are installed into `usr/share/icons/hicolor/{scalable,symbolic}/apps/` via the existing `cargo-deb`/`cargo-generate-rpm` asset-list mechanism, and the `.desktop` file gets an `Icon=mediamerger` line.

**Tech Stack:** Rust, `iced` 0.14 (`mediamerger-app`), new `image` crate dependency (PNG decode only).

## Global Constraints

- No PNG hicolor installs — only the scalable SVG and symbolic SVG get packaged, per the design doc's explicit non-goal (modern GNOME renders scalable SVG at any size; the design bundle's own packaging guidance only calls for these two files).
- The new icon assets are unrelated to `mediamerger-app/src/ui/icons.rs`'s existing small monochrome UI glyphs (toolbar/button icons, recolored at runtime) — keep them in their own directory (`assets/app-icon/`), not mixed into `assets/icons/`.
- Verify any newly-added crate's API (`image`, in this case) against its actually-installed source once `cargo build` fetches it, per this project's established practice of confirming APIs empirically rather than from training-data recall — even though the API used here (`load_from_memory`, `.into_rgba8()`, `.dimensions()`, `.into_raw()`) is standard and unlikely to have changed, a quick check costs little and this project's convention doesn't make exceptions for "probably stable" APIs.

### Task 2: Wire the running window's icon

**Files:**
- Modify: `mediamerger-app/Cargo.toml`
- Modify: `mediamerger-app/src/main.rs`

**Interfaces:**
- Consumes: `mediamerger-app/assets/app-icon/mediamerger-128.png` (Task 1).
- No signature change to any existing function — adds one new private function (`load_window_icon`) and one field to an existing struct literal.

- [ ] **Step 1: Add the `image` crate dependency**

In `mediamerger-app/Cargo.toml`, add to `[dependencies]` (after the existing
`dark-light = "1"` line):

```toml
image = { version = "0.25", default-features = false, features = ["png"] }
```

`default-features = false` + `features = ["png"]` keeps this to a PNG-only
decoder — this project has no need for the other image formats the `image`
crate supports by default.

- [ ] **Step 2: Add a window-icon loader function to `main.rs`**

Add near the other `detect_*`/`check_*` helper functions (e.g. right after
`detect_accent_color`, before `fn subscription`):

```rust
fn load_window_icon() -> Option<window::Icon> {
    let bytes = include_bytes!("../assets/app-icon/mediamerger-128.png");
    let image = image::load_from_memory(bytes).ok()?.into_rgba8();
    let (width, height) = image.dimensions();
    window::icon::from_rgba(image.into_raw(), width, height).ok()
}
```

Verify `image::load_from_memory(&[u8]) -> ImageResult<DynamicImage>`,
`DynamicImage::into_rgba8() -> RgbaImage`, `RgbaImage::dimensions() -> (u32,
u32)`, and `RgbaImage::into_raw() -> Vec<u8>` against the actually-fetched
`image` crate source (`~/.cargo/registry/src/*/image-0.25.*/src/`) once
`cargo build` pulls it in — these are long-stable, widely-used APIs, but
this project's practice is to verify empirically rather than assume, even
for APIs that are unlikely to have changed.

- [ ] **Step 3: Set the icon in `window::Settings`**

Change the `.window(window::Settings { ... })` call in `main()`:

```rust
        .window(window::Settings {
            platform_specific: window::settings::PlatformSpecific {
                application_id: "mediamerger".to_string(),
                ..Default::default()
            },
            icon: load_window_icon(),
            ..Default::default()
        })
```

- [ ] **Step 4: Build and test**

Run: `cargo build --workspace`
Expected: zero errors. If any of Step 2's API signatures don't match the
fetched `image` crate version exactly, adapt per the real source — don't
guess further, and don't fall back to skipping the icon silently succeeding
via `.ok()` chains without first confirming the real API shape.

Run: `cargo test --workspace`
Expected: all passing (no new testable logic — `load_window_icon`'s only
failure mode is a malformed/missing embedded asset, which would be a build-time
`include_bytes!` failure, not a runtime-testable condition).

- [ ] **Step 5: Commit**


**Files:**

**Interfaces:**

- No code interfaces — packaging metadata and a desktop-entry file only.

- [ ] **Step 1: Add `Icon=` to the desktop entry**

Add `Icon=mediamerger` to `mediamerger-app/assets/mediamerger.desktop`
(after the `Name=MediaMerger` line):

```ini
[Desktop Entry]
Type=Application
Name=MediaMerger
Icon=mediamerger
Comment=Merge video and audio from two encodes of the same movie into a synced MKV
Exec=mediamerger
Terminal=false
Categories=AudioVideo;Video;
StartupWMClass=mediamerger
```

`Icon=mediamerger` references the icon *by name* (no path) — this is the
standard freedesktop convention; it resolves via the hicolor theme once the
files below are installed, matching the file basenames (without extension).

- [ ] **Step 2: Add the icon files to the `cargo-deb` asset list**

In `mediamerger-app/Cargo.toml`'s `[package.metadata.deb]` section, add two
entries to the existing `assets` list (source paths relative to
`mediamerger-app/`, matching the existing `assets/mediamerger.desktop`
entry's convention exactly):

```toml
assets = [
    ["target/release/mediamerger", "usr/bin/", "755"],
    ["assets/mediamerger.desktop", "usr/share/applications/", "644"],
    ["assets/app-icon/mediamerger.svg", "usr/share/icons/hicolor/scalable/apps/", "644"],
    ["assets/app-icon/mediamerger-symbolic.svg", "usr/share/icons/hicolor/symbolic/apps/", "644"],
]
```

- [ ] **Step 3: Add the icon files to the `cargo-generate-rpm` asset list**

Add two new `[[package.metadata.generate-rpm.assets]]` blocks to
`mediamerger-app/Cargo.toml`, after the existing `.desktop` file block
(source paths relative to the workspace root, matching the existing
`mediamerger-app/assets/mediamerger.desktop` entry's convention exactly —
note this differs from the `cargo-deb` list's crate-relative convention
above; that's an existing, pre-established difference between the two
tools' path resolution in this file, not something to "fix"):

```toml
[[package.metadata.generate-rpm.assets]]
source = "mediamerger-app/assets/app-icon/mediamerger.svg"
dest = "/usr/share/icons/hicolor/scalable/apps/mediamerger.svg"
mode = "0644"

[[package.metadata.generate-rpm.assets]]
source = "mediamerger-app/assets/app-icon/mediamerger-symbolic.svg"
dest = "/usr/share/icons/hicolor/symbolic/apps/mediamerger-symbolic.svg"
```
